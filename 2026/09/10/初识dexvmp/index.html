通过[原创]APP加固还原dexvmp-Android安全-看雪安全社区｜专业技术交流与安全研究论坛 这个来认识一下vmp. 但是360现在好像没法个人免费加固了, 我就用了一个其他的项目来复现.maoabc/nmmp: dex-vm used to protect the android classes.dex file


这是原来的apk, 可以看到dex的方法都可以还原

加了vmp之后, dex的方法全都被抽走了, 只剩native的声明, 然后在lib文件夹下面出现了两个so文件, 这两个肯定一个是vm解释器, 一个负责装载

先hook一下RegisterNatives, 当壳执行 classesInit0(0) 时，读出它提交的表

表上的函数名确实和我们在jadx里面看到的是一样的, 这些地址都是方法入口, 里面的代码是被翻译过的假代码.

接下来直接在libnmmp.so里面看一下入口, 以oncreate为例子

这里就是从libnmmp.so 找到 libnmmvm.so的关键, 最后一行, libnmmp.so 把 onCreate 的虚拟指令、寄存器、resolver 打包进 v5, 然后调用 vmInterpret（libnmmvm.so 的导出函数）, 之后真正“翻译”的活，全部在 vmInterpret 内部完成.

先看看 onCreate的假指令, 按 16-bit 小端读成 49 个 code units

接下来打开 libnmmvm.so找 opcode 表（handler 表）

在导出表里面找到vmlnterpret, 这是函数入口

反编译明显不对, 只能看汇编了
